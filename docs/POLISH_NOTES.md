## Timing evidence

The follow-up reconstruction pass corrects the cloud upsampler's Catmull-Rom kernel. Its four-tap shortcut combined negative outer weights with positive neighbours, causing lookups to leave the intended texel pair. The replacement combines only the two positive centre weights and evaluates the full footprint in nine taps. `npm run test:cloud-filter:browser` compares the actual GPU shader against an independent sixteen-sample CPU reconstruction at non-integer magnification. The sharp-edge maximum error fell from 6.74% to 0.20%, and RMS error from 1.63% to 0.029%. Smooth billow error fell from 3.71% to 0.068%. The remaining error is within hardware bilinear interpolation precision. This corrects spatial reconstruction; it does not promise to remove all raymarch or temporal sampling noise.

The live low-preset capture measured 100.6 ms median animation frames, but an **empty** animation loop in the same browser measured 100.3 ms. The 10 FPS cadence is therefore not evidence of a 100 ms game-rendering cost. Median CPU time inside `App.render` was 24.5 ms; reported GPU zones totalled about 5.1 ms (clouds 0.73 ms, scene 1.67 ms, underwater 1.83 ms). Future performance work should inspect CPU submission/update cost and use a browser scheduling baseline before reducing visual quality. These measurements do not establish frame rates in the user's visible browser.

After the nine-tap correction, the same live harness measured clouds at 0.703 ms, median CPU render time at 25.6 ms, and an empty animation loop at 100.4 ms. The cloud cost remains in the previous range; this live comparison is not a controlled microbenchmark. The production build, fresh GPU boot, keyboard/mouse checks and all six weather/altitude review views passed. Low-preset temporal and horizon sampling grain remains visible, especially at dusk.
